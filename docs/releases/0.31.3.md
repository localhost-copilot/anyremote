## Fixed in 0.31.3

- **A slow connection recovers instead of falling further behind.** When the network couldn't carry the picture, every lost frame asked the other Mac for a full new picture, and on a slow link each of those was lost in turn: the picture could stay half a second behind with frames missing for as long as the link stayed slow. AnyRemote now waits for one full picture to arrive before it sends the next. Through a 15 Mbit/s link, the picture caught up within 4 seconds and then stayed about 15 ms behind with nothing lost.
- **Video quality also lowers when the network starts queuing.** Besides lost frames, AnyRemote now notices when frames wait in a router's or Wi‑Fi's buffers, and lowers the quality before frames start getting lost.
- **A stuck video encoder no longer freezes a window.** If the other Mac's hardware video encoder stops answering (another app holding it, or the encoder hanging), AnyRemote starts it afresh after a second, and falls back to software encoding when it hangs again, trying the hardware once more later.

## Install

Requires macOS 15 or later (universal: Apple silicon and Intel).

AnyRemote 0.26.0 and later offer this update by themselves, or use AnyRemote › Check for Updates…. To install by hand, unzip `AnyRemote-0.31.3.zip` into `/Applications`. Then clear the quarantine flag once:

```sh
xattr -dr com.apple.quarantine /Applications/AnyRemote.app
```

0.31.3 uses protocol v24, like 0.31.0, so it works with Macs still on that. Most fixes are on the Mac being controlled; the queuing signal comes from the Mac you control it from, so update both.
